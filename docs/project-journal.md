# 记得要吃药 — 项目笔记

## 一、项目缘起

**问题**：爸妈老了，经常忘记吃药。市面上提醒 APP 太复杂，广告多，老人用不来。

**想法**：做一个老人真正能用的——打开就看到药、点一下就完事、到时间会叫。

## 二、设计过程

### 适老化设计的核心原则

- 超大字体 28px，按钮 60px 高
- 主色 #165DFF，高对比度白底
- 老人只看一页：今日药品 + "我吃过了"按钮
- 子女操作（添加药品、查看记录）藏在 ⚙️ 设置里

### 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 布局 | 纵向滚动单列 | 零学习成本 |
| 药品展示 | 照片 + 大字 | 不识字老人也能认 |
| 语音播报 | 中文语音 + 蜂鸣兜底 | 华为等国产浏览器不支持 speechSynthesis |
| 按钮交互 | 只能"已吃"和"未吃"，无"补吃" | 医疗常识——药不能乱补 |
| 已错过 | 红色卡片 + 灰色按钮，不可操作 | 错过就是错过了 |
| 存储 | localStorage + IndexedDB | 数据只在手机，不上传 |

### 踩过的坑

1. **语音播报不响**：浏览器安全策略，`speechSynthesis` 必须用户先交互一次才能触发。加了静默解锁 + Web Audio API 蜂鸣兜底。

2. **华为浏览器不支持 PWA 安装**：`beforeinstallprompt` 事件不触发。最后用 PWABuilder 生成 APK 解决。

3. **苹果 Safari 安装**：没有自动弹出提示，加了 iOS 手动指引（分享 → 添加到主屏幕）。

4. **"我忘记吃了"按钮逻辑矛盾**：点了变"已吃"但文字说不通。最终设计——过期的药按钮置灰不可点，避免误导。

## 三、开发方式：Claude Code 全流程 AI 编程

整个项目用 **Claude Code** 完成，零手写代码。

### 为什么用 Claude Code

以前做项目要自己写 HTML/CSS/JS，调试各种细节。这次换个思路——把需求说清楚，让 AI 来写。

### 开发流程

**1. 设计沟通（先聊再写）**

没有一上来就写代码。先用 Claude Code 的视觉伴侣功能，在浏览器里做手机 mockup，三种布局方案放在一起比较。最终选了"A：纵向滚动单列"。

这个过程像跟设计师开会——你说想法，它给你看效果，点了不要就换。

**2. 细节点反复打磨**

- 老人不识字的场景 → 加了拍照功能
- "添加药品"和"今日待服"混在一起不好 → 拆成老人视图 + 子女管理视图
- "我忘记吃了"点了变"已吃"逻辑矛盾 → 讨论后确定"过了就是过了，不能补"

每次都是聊着聊着发现问题，当场改设计。

**3. 实施计划 + 代码生成**

设计定下来后，Claude Code 自动生成了一份 12 步实施计划，从数据层到 CSS 到语音播报到 PWA 配置，每步都有完整代码。然后按计划逐步构建，每一步提交一个 commit。

**4. 真机测试 + 修 bug**

手机上测试发现华为浏览器语音不响 → 加了蜂鸣兜底。测试语音按钮后来也去掉了，保持界面干净。

### 使用感受

| 方面 | 体验 |
|------|------|
| 设计阶段 | 最好用的部分。视觉伴侣直接看效果，不用脑补 |
| 写代码 | 完全不用手写，12 个任务自动完成 |
| 改 bug | 描述问题 → 修复 → 提交，很顺畅 |
| 总体效率 | 从想法到成品，一个下午 |

## 四、技术栈

- 纯 HTML + CSS + Vanilla JavaScript
- 零框架、零依赖、零服务器
- localStorage（药品数据）+ IndexedDB（药盒照片）
- Service Worker（离线缓存）
- Web Speech API（语音播报）
- Web Audio API（蜂鸣闹铃兜底）

## 五、项目结构

```
RememberMeds/
├── index.html          # 全部代码（HTML/CSS/JS 单文件，约1200行）
├── manifest.json       # PWA 配置
├── service-worker.js   # 离线缓存 + 后台
├── icon-192.png        # APP 图标
├── icon-512.png        # APP 图标
├── docs/               # 设计文档 + 计划

```
